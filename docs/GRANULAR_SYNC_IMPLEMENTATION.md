# Granular sync implementation and release gate

Approved behavior: HA owns all UDP; streaming suspends normal zone output; pause/quit/disconnect/timeout restores untouched manual zone states. Manual changes while owned return an explicit error. No live deployment during development.

Wire contract: authenticated Hyperion-compatible WebSocket from ScreenEdges, 80 RGB samples ordered left/top/right/bottom (20 each). HA resamples each selected edge to the section count allocated from HA zone lengths, reverses per destination when configured, and composes exactly 20 physical sections per strip. Multiple destinations may select the same edge. Missing mappings paint black. Physical inset strip lengths do not crop screen coordinates.

Control contract: authenticated HA HTTP endpoint exposes eligible zone layout, starts a stream from the requesting Mac's IP and supplied listening port/token, and releases only the matching owner. No arbitrary remote host is accepted. Frames must be valid and timely. Unknown/duplicate entities, conflicting ownership, invalid samples, authentication failure, and unsupported frame lengths fail without losing manual state.

Release gate:
1. Pure sampler/mapping/packet tests, including orientation and legacy config migration.
2. Ownership/release/timeout/error/concurrent-command lifecycle tests, with fake UDP output.
3. Real local HTTP/WebSocket integration test using the exact Swift producer and Python consumer. No household HA involved.
4. Release Swift build; Python import/manifest checks against target HA version; bounded reconnect/soak test; review resulting diff.
5. Prepare versioned artifacts, rollback instructions and checksum list. Deploy one validated bundle in a coordinated window. Installing new Python module code may require one HA Core restart even though normal configuration changes use integration reload; never claim an integration reload reloads imported Python source.

Desk zone lengths/direction remain user measurements. Existing single bottom desk zone migrates without inventing three lengths.

## Reproduce the local checks

Use CPython 3.14 with Home Assistant 2026.10.2, pytest, pytest-asyncio and pytest-aiohttp in a local environment. No household HA URL, credentials or UDP devices are used. The endpoint tests use HA's actual authentication middleware; only the output engine is recorded. A second Swift fixture mode also exercises the app's production HA HTTP control client: discovery, typed layout decoding, start, reversed granular output and release.

```sh
# In the screen-edges repository
swift test
swift build -c release
# In this repository (point SWIFT_STREAM_FIXTURE at that release build)
SCREEN_SYNC_SOAK_SECONDS=60 SWIFT_STREAM_FIXTURE=/path/to/screen-edges/.build/release/screen-edges-stream-fixture .venv-screen-sync/bin/python -m pytest -q custom_components/localtuya/tests/test_granular_sync.py custom_components/localtuya/tests/test_screen_layout.py
PYTHONPATH=. .venv-screen-sync/bin/python tests/test_zone_sender.py
```

The committed Node golden fixture was generated by `battletron-zones/granularity.js`'s hardware-tested `palettePayload`. It covers the full 20-color palette, the legacy four-color frame, and HSV half-rounding; the Python payload must match byte for byte. Also run `node --test granularity.test.js` in that repository.

The painter shutdown tests reproduce single and double cancellation and require worker completion before socket closure. Unload tests prohibit restoration into closing devices. Source tests cover invalid auth/frames, timeout despite non-frame spam, startup cancellation, power failure rollback, conflicting owners, stranger releases, repeated starts without session churn, ten pause/resume cycles and abrupt process termination. These are software tests; they do not establish long-duration physical controller stability or final wiring orientation.

## One coordinated deployment

Prepare and verify both versioned artifacts and SHA-256 checksums first. Do not use the obsolete ScreenEdges pkg installer. The signed app zip contains the release build; the LocalTuya zip contains the integration directory for HACS/manual packaging. Do not publish a HACS tag until the release gate passes. Archive exact sources and validation results with the candidate.

At the agreed window:

1. Save the installed component version, existing app bundle and LaunchAgent, and an owner-only backup of the Mac config. Save the current HA manual zone states. Keep secrets out of release archives.
2. Pause and stop the old ScreenEdges process before upgrading HA, so its legacy `light.turn_on` calls cannot compete with the new ownership protocol.
3. Publish/install the validated LocalTuya release through HACS once. Restart HA Core once to load the new Python modules; an integration reload alone does not reload imported Python source. Wait until HA is fully running and normal manual lights work.
4. Replace the Mac app with the validated signed 1.1.0 bundle, preserving the existing bundle identifier/signing certificate and LaunchAgent. Existing config mappings migrate on first launch. Do not start extra Node senders.
5. Start sync once. Confirm left/top/right and bottom with a spatial gradient, then Pause and confirm restoration of saved manual states. Check Quit/relaunch and source-loss restoration. Capture a brief log sample; never log tokens.
6. Keep the existing single bottom desk zone until lengths and controller direction are confirmed. Add 1d/2d/3d in one configuration change, then map left/bottom/right and reverse as needed.

If this acceptance check fails, stop the new app and restore both previous component and app artifacts plus the Mac config backup. Use one planned rollback HA restart if Python code was replaced. Return to ordinary manual lighting; investigate offline before another release. Do not iterate small patches on the household HA.
